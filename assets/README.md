# 按钮模板素材

## 目录

```
assets/
  screens/      ← 你放的原始按钮截图（留档）
  templates/    ← 程序实际读取的模板
```

## 模板清单

| 文件 | 对应按钮 | 说明 |
|---|---|---|
| `btn_battle.png` | 主界面「对战」 | 普通外观（只有"对战"两字） |
| `btn_battle2.png` | 主界面「对战」 | 带"每日额外奖励"小字的外观 |
| `btn_mode_1v1.png` | 模式菜单「经典1对1」 | 整行，含国王像和交叉剑图标 |
| `btn_ok.png` | 结算页「确定」 | 蓝色按钮 |

## 同一个按钮可以挂多个模板

游戏里按钮外观会变，**一个按钮对应多个模板**，程序取匹配分最高的那个：

- 「对战」在**每日额外奖励可领**时会多一行小字 → `btn_battle2.png`；
- 版本更新改了按钮画风 → 再补一个 `btn_battle3.png`，并把它加进
  `src/ui_buttons.cpp` 顶部的 `kSpecs` 里（每个按钮最多 4 个外观）。

这就是为什么之前另外四台设备一直卡住：它们的「对战」按钮带"每日额外奖励"小字，
和第一台的普通版对不上（分数只有 0.2 左右），于是永远判不出主界面。

## 每个按钮的搜索范围

模板只在固定区域内搜（`kSpecs` 里的 `Rect roi`，720x1280 坐标）：

| 按钮 | 搜索范围 |
|---|---|
| 对战 | x 210..520, y 900..1120 |
| 确定 | x 255..475, y 1040..1180 |
| 经典1对1 | 全屏（列表会滚动，位置不固定） |

如果换了分辨率或界面大改，改这里的 `Rect` 即可，不用动匹配算法。

## 裁剪注意

- 模板要比按钮本体**外扩几像素**，保留边框和投影；
- 避开会呼吸的高光/闪光区域，否则同一按钮不同帧的分数会抖；
- 匹配用归一化相关系数（NCC），阈值 `0.72`（对战/确定）、`0.80`（1对1）。
